# Настройка Google (Sheets): инструкция для заказчика

Цель: чтобы Ассистент мог дописывать заявки в вашу Google-таблицу. Для этого создаётся
**service account** (служебный аккаунт): робот со своим email и ключом. Вы даёте этому email доступ
к таблице, как обычному коллеге. Ничего знать заранее не нужно.

Названия кнопок взяты из документации Google Cloud:
[создание service account](https://docs.cloud.google.com/iam/docs/service-accounts-create),
[создание ключа](https://docs.cloud.google.com/iam/docs/keys-create-delete),
[включение API](https://developers.google.com/workspace/guides/enable-apis). Интерфейс обновляется,
и консоль может быть на русском: ищите кнопку по смыслу, а если что-то не находится, напишите
разработчику.

## Что понадобится

- Google-аккаунт, которым вы владеете таблицей.
- Ваша рабочая CRM-таблица в Google Sheets. Ассистент сам создаст в ней **отдельный лист `Leads`**
  и будет писать заявки только туда. Ваши листы и колонки он не трогает. Если таблицы ещё нет, подойдёт
  новая пустая: [sheets.google.com](https://sheets.google.com) -> **Blank** (Пустой файл).

## Шаг 1. Проект в Google Cloud

1. Откройте [console.cloud.google.com](https://console.cloud.google.com) и войдите. При первом входе
   согласитесь с условиями. Платёжная карта для этой инструкции не нужна.
2. Вверху слева, рядом с логотипом Google Cloud, нажмите на выпадающий список проектов
   (**Select a project**), затем **New Project**.
3. Название: например `lead-assistant`. Нажмите **Create**, дождитесь создания и выберите этот
   проект в том же выпадающем списке.

## Шаг 2. Включить Google Sheets API

1. Меню (три полоски слева вверху) -> **APIs & Services** -> **Library**.
2. В поиске введите `Google Sheets API` и откройте найденный результат.
3. Нажмите **Enable**. Если вместо кнопки написано **Manage**, API уже включён.

## Шаг 3. Создать service account

1. Меню -> **IAM & Admin** -> **Service Accounts**, затем **Create service account**.
2. **Service account name**: например `lead-assistant`. Поле **Service account ID** заполнится само
   (потом его изменить нельзя). Описание можно не заполнять.
3. Нажмите **Create and continue**. Роли выдавать не нужно: шаг с доступом к проекту пропустите
   кнопкой **Continue**, на следующем нажмите **Done**.
4. Если сразу после создания аккаунт недоступен, подождите минуту.
5. В списке появится строка с **email** вида `lead-assistant@lead-assistant-123456.iam.gserviceaccount.com`.
   Скопируйте его. Это `GOOGLE_SERVICE_ACCOUNT_EMAIL`.

## Шаг 4. Скачать JSON-ключ

1. В списке **Service Accounts** нажмите на email созданного аккаунта.
2. Откройте вкладку **Keys**.
3. Нажмите **Add key** -> **Create new key**.
4. Выберите тип **JSON**, нажмите **Create**.
5. Файл `.json` скачается автоматически. Повторно скачать его нельзя: если потеряете, создайте новый
   ключ. В файле есть поля `client_email` (тот же email, `GOOGLE_SERVICE_ACCOUNT_EMAIL`) и
   `private_key` (длинная строка, начинается с `-----BEGIN PRIVATE KEY-----`,
   `GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY`).

Если создание ключа блокируется политикой организации (`iam.disableServiceAccountKeyCreation`),
значит ключи запрещены в вашей организации Google Cloud (бывает у аккаунтов Google Workspace и у
организаций, созданных после 3 мая 2024). Обычный личный gmail-аккаунт с этим не сталкивается.
Решение: администратор организации снимает запрет для этого проекта, либо вы создаёте проект под
личным gmail. Напишите разработчику.

## Шаг 5. Расшарить таблицу на service account

1. Откройте таблицу и нажмите **Share** (Настройки доступа) в правом верхнем углу.
2. В поле добавления людей вставьте email service account из шага 3.
3. Справа выберите роль **Editor** (Редактор). Читателя недостаточно: Ассистент записывает строки.
4. Если есть галочка **Notify people**, снимите её: письмо роботу не нужно. Нажмите **Share** / **Send**.
   Если Google спросит про приглашение внешнему адресу, подтвердите.

## Шаг 6. Найти ID таблицы

Откройте таблицу и посмотрите на адрес в браузере:

```
https://docs.google.com/spreadsheets/d/1AbC...xyz/edit#gid=0
```

Строка между `/d/` и `/edit` (здесь `1AbC...xyz`) и есть ID таблицы. Это `GOOGLE_SHEETS_SPREADSHEET_ID`.
Название листа сообщать не нужно: заявки пойдут на отдельный лист `Leads`. Если лист с таким именем
у вас уже есть и занят чем-то другим, скажите разработчику: он выберет другое имя.

## Шаг 7. Дать разработчику посмотреть таблицу

Колонки листа `Leads` (дата, канал, имя, контакт, услуга, описание, желаемая дата, намерение, статус,
ID беседы) согласуем с вами, глядя на вашу таблицу. Для этого через **Share** добавьте Google-аккаунт,
который пришлёт разработчик, с ролью **Viewer** (Читатель). Скажите, если хотите другие колонки
или другой порядок.

## Что прислать разработчику

| Что | Откуда | Переменная |
|---|---|---|
| Email service account | Шаг 3 | `GOOGLE_SERVICE_ACCOUNT_EMAIL` |
| JSON-ключ целиком (или значение `private_key`) | Шаг 4 | `GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY` |
| ID таблицы | Шаг 6 | `GOOGLE_SHEETS_SPREADSHEET_ID` |
| «Разработчику открыт просмотр таблицы» и пожелания по колонкам | Шаг 7 | — |

JSON-ключ даёт доступ ко всем таблицам, расшаренным этому аккаунту. Как передавать безопасно:

- Не вставляйте содержимое ключа в открытый чат, почту, задачи и не публикуйте файл в репозитории.
- Используйте менеджер паролей с общим доступом, одноразовую ссылку
  (например, [onetimesecret.com](https://onetimesecret.com)) или зашифрованный чат (Signal, секретный чат
  Telegram). Можно положить файл в архив с паролем, а пароль отправить другим каналом.
- После передачи удалите файл с компьютера и из загрузок. Если ключ утёк: в Google Cloud откройте
  аккаунт -> **Keys**, удалите старый ключ (значок корзины), создайте новый и пришлите его.
